# 数字スロット 777

パチスロ風の演出をまとった数値抽選アプリ。1人用の抽選モードと、複数端末リアルタイム同期のオンライン対戦モードを備えます。

- 外部APIキー不要（Geminiは未使用のため依存ごと削除済み）
- ログイン・課金・データベース不要。サーバーはメモリ上の一時ルームのみを保持
- PWA対応（ホーム画面に追加してフルスクリーン起動）

---

## セットアップ

Node.js 20以上が必要です。

```bash
npm install
npm run lint      # 型チェック
npm run dev       # http://localhost:3000
```

本番ビルドの確認:

```bash
npm run build && npm start
```

成果物は `dist/client/`（フロントエンド）と `dist/server.cjs`（同期サーバー）に出ます。

## 対戦のルール

### 基本

- 参加人数は最大8名（サーバーの枠上限）
- 各プレイヤーは持ち点 **5ポイント** で開始
- **数値が小さいほど強い**。全員の手番が終わった時点で最小の人が勝ち

### 1回転の消費

「スキル代 + 1ポイント」。スキルなしなら1回転1ポイントなので、1ターンで最大5回転できます。

### スキル

| スキル | 消費 | 効果 |
|---|---|---|
| 次回 -20 | 1pt | 次の1回転の結果から20引く |
| 次回 -40 | 3pt | 次の1回転の結果から40引く |
| ターン中 -5 | 1pt | そのターン中の全回転から5引く |

「次回 -20」と「次回 -40」は**排他**です。片方を選ぶともう片方が外れます。

### ⚡乱数調整（空回転）

ポイントを消費せず、スキルも乗らず、**結果がスコアになりません**。回して見るだけのボタンです。

### スコア

確定値からスキル減算を引いた数がスコアです。**下限はありません**。素の出目3に -40 を乗せれば -37 になります。

持ち点が0になると自動的に手番終了。残っていても「数値確定」でいつでも手番を終えられます（誤操作防止のため2段階タップ）。

### 得点計算

最小スコアの人が勝ち。同点で並んだら引き分けで全員±0。

勝者の獲得ポイント:

| 条件 | 獲得 |
|---|---|
| 勝ちスコアがマイナス | +4000 |
| 勝ちスコアが10以下 | +3000 |
| それ以外 | +2000 |

敗者は勝者との**点差に比例**して支払い、合計が勝者の獲得額と一致します。

### ゾロ目ボーナス（順位と無関係）

持ち点5を使い切った上でゾロ目（111、333 など）を出した人は、**順位を問わず +3000**。原資はそれ以外の全員が等分で負担します。順位点とは完全に独立しているため、3位でもゾロ目を出せば1位より稼げます。複数人が同時にゾロ目でも、それぞれ独立に精算するので収支は必ずゼロサムです。

### 周とセット

**1セット = 人数分の周**です。3人なら3周、2人なら2周でセット終了。周が変わるたびに先頭の手番が1つずれます。

セット終了時の選択肢は3つ。

- セットの結果をみる（履歴・成績）
- 次のセットへ進む（手番回転）
- これまでの結果を見て終了

累積ポイントはセットをまたいで持ち越されます。セット数に上限はありません。

## オンライン対戦

「対戦」タブでルームIDとユーザー名を入力して入室します。ルームIDは半角英数字と `-` `_` のみ、32文字まで。

既定は `GLOBAL_LOBBY` で、**URLを知っている人は誰でも入れます**。身内だけで遊ぶ場合は `TANAKA-2026` のような固有のIDに変更してください。

同期はSSE（サーバープッシュ）が主、ポーリングが保険の二重構成です。レバーON・リール停止・スタンプ・集計結果・周とセットの進行は、すべての端末に即時反映されます。

**再入室に対応しています。** 端末IDを localStorage に保存しているため、タブを閉じても再読み込みしても同じプレイヤー番号に戻れます。枠は3時間予約されます。

対戦中に誰かが新規入室しても、進行中の試合はロビーに戻されません。

## デプロイ（Render 無料プラン・クレジットカード不要）

1. GitHubにリポジトリを作成し、このフォルダを push（ブランチ名は `main`）

```bash
git init && git add -A && git commit -m "数字スロット 777"
git branch -M main
git remote add origin https://github.com/<あなたのID>/slot-777.git
git push -u origin main
```

2. https://render.com にGitHubアカウントでサインアップ
3. **New → Blueprint** → リポジトリを選択 → **Apply**

`render.yaml` により、ビルド `npm ci && npm run build`、起動 `npm start`、ヘルスチェック `/api/health` が自動設定されます。

### スマホでの使い方

発行されたURLをSafariで開き、**共有 →「ホーム画面に追加」**してください。Safariのアドレスバーが出たままだと画面が約90px削られ、対戦画面がスクロールなしに収まりません。ホーム画面から起動すればフルスクリーンになります。

### 無料プランの挙動

- **誰か1人でも接続していればスリープしません。** SSE常時接続とポーリングでリクエストが途切れないためです。長時間の連続対戦も可能です
- 全員が15分以上離れるとスリープし、進行中のルーム状態は失われます。復帰には30〜60秒かかります
- メモリ512MB・月750時間まで無料

### 他のプラットフォーム

`Dockerfile` を同梱しています。Cloud Run / Fly.io / Koyeb などにも載ります（いずれもカード登録が必要）。`PORT` 環境変数を自動で読みます。

## 設定スイッチ

### 出目の分布

`src/utils/effects.ts` の `STRICT_UNIFORM_DISTRIBUTION`。

| 値 | 挙動 |
|---|---|
| `true`（既定） | 演出は残したまま、出目は必ず抽選どおり。実測で完全な一様分布 |
| `false` | 「400以上を引いたが99以下を見せる」演出の半分がそのまま確定する救済が働き、1〜99が約1.13倍出やすくなる |

抽選は `crypto.getRandomValues` によるモジュロバイアス除去済みの実装です。

### 演出の頻度

- 違和感演出（9種類）の発生率は `src/utils/effects.ts` の `p_success + 0.55` の数値
- カットインの頻度は設定画面から「高・通常・低」で変更可能
- 抽選範囲の上限は設定画面から1〜999で変更可能

## サーバーの安全設計

`/api/sync/state` は認証なしの公開エンドポイントのため、以下を実装しています。

- 受け取るフィールドをホワイトリスト化し、すべて範囲チェック（不正な値はクランプまたは拒否）
- ルームIDの形式検証、ルーム数上限500、3時間のTTLとLRU退避
- ペイロード上限64KB、書き込みのレート制限（10秒あたり120回／IP）
- SSE接続数の上限、20秒ごとのハートビート
- セキュリティヘッダ、プロトタイプ汚染対策
